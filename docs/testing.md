# Testing

[← Documentation index](README.md)

```bash
python -m pytest -q                                  # the whole suite, ~27 s
python -m pytest -q --cov=main --cov=ptcg --cov-report=term-missing
```

The suite is large — **2 249 tests across 203 files** as of 11 August 2026 — and
fast. It is the first gate for any change. What follows is **what each kind of
test protects**, because they are not interchangeable.

`pytest.ini` pins `testpaths = tests`, and that is not cosmetic: a self-play gate
copies the whole tree, suite included, into `log/<gate>/base_tree/`, so a bare
`pytest` that walks the repository collects both copies and dies on basename
collisions. It never showed up in CI, because `log/` is git-ignored — the
documented first gate was red locally and green on a clean checkout.

## 1. Behaviour tests — one per lesson learned

The bulk of `tests/` is one file per strategic rule, named after the rule:
"don't gust a non-ex pre-evolution", "promote the mobile attacker, not the wall
pinned in front", "play the Supporter before retreating". Each one sets up a
board and asserts the agent's choice.

They exist because every one of those rules was once wrong and cost games. They
are the memory of the project — the reason a fixed mistake does not come back.

## 2. Fixtures — real boards, frozen

`tests/fixtures/` holds observations captured from real games, saved as
self-contained JSON. They pin decisions against positions that actually
happened, without depending on the throwaway game records in `records/`.

Use one when the situation is real and you can capture it.

## 3. The scenario builder — boards that never happened

`tests/state_builder.py` builds synthetic observations: edge cases, parametric
sweeps, positions no real game produced. It does **strict accounting** of all 60
cards — every card you place in a zone is deducted from a pool, and at build
time the remainder must be exactly the number of face-down prizes. An impossible
board raises a clear error instead of quietly producing an observation that
would confuse the agent's card tracking.

Use one when the situation is hypothetical or you need many variations.

## 4. Invariants — properties that must always hold

`tests/test_invariants.py` uses property-based testing: hundreds of valid
generated boards, checked against properties that must hold on **all** of them:

- the agent never raises and never returns an invalid choice on a legal board —
  an exception in a real game is an instant loss;
- documented caps are respected across the whole generated space.

Examples are deterministic per code version, so the suite never flakes; when an
invariant breaks, the failing board is shrunk to the minimal counterexample.

> This file needs `hypothesis`. Without it, pytest aborts the entire run with a
> collection error rather than skipping.

## 5. The golden corpus — which decisions your change flipped

`tests/golden_corpus.py` replays stored games through the agent and compares
against a snapshot of past decisions. Behaviour tests cover the decisions that
already hurt; the corpus covers *all* of them, so an unintended flip surfaces
before it ships.

```bash
python tests/golden_corpus.py               # compare (non-zero exit on differences)
python tests/golden_corpus.py --update      # review the diff, then accept it
```

There are **two** corpora, and they behave differently on purpose.

**The local one** (`tests/test_golden_corpus.py`) reads `records/`, which is
transient game data:

- no records (fresh clone) → skipped;
- no snapshot → bootstrapped, compares from the next run;
- records replaced or added → the snapshot self-heals, since those files are
  local throwaway data;
- **same record, different decision → failure**, with the exact diff. Accept it
  consciously with `--update` if the flip is what you intended.

Records are generated by `utils/record_corpus.py` or `utils/split_turns.py` —
see [Tools](tools.md).

**The frozen one** (`tests/corpus/`, checked by
`tests/test_the_frozen_corpus_runs_on_a_clean_checkout.py`) is committed:
fifty games reduced to only *our* decisions, 0.85 MB gzipped, with its snapshot
beside it. It exists because the flip-diff is the most useful review artefact
this project produces, and it was the one artefact a reviewer on a clean
checkout could not see. It **cannot** self-heal — it is versioned by git, so a
flip is a flip and the diff is the finding, which is what makes it usable as a
CI gate.

Accepting a reviewed flip in the frozen corpus is
`python utils/freeze_corpus.py --snapshot-only`. The bare command rebuilds the
bundle from whatever games are in your `records/` — usually a handful against
the fifty committed — and the bundle is a gzip, so the commit diff would not
show what was lost. `tests/test_freeze_corpus_does_not_shrink_the_gate.py`
guards exactly that.

## 6. Submission smoke test — the container, not pytest

`tests/test_submission.py` covers the one gap the rest of the suite cannot see.
Under pytest, the agent is a normally imported module with the project root
permanently on the path. In the competition container it is neither: the loader
compiles the file, executes it in an empty namespace with the directory on the
path only during that execution, and keeps the **last callable it finds**.

Three failure modes are checked, all of which would pass every other test while
breaking the real submission:

- a local package imported for the first time mid-game → module not found,
  mid-battle;
- anything that binds a new callable after the agent entry point (including a
  compatibility re-export, and note that a class is callable too) → the
  container picks *that* as the agent. Silent and fatal;
- the agent module never enters the module registry, so no submodule can import
  it back.

## 7. Architecture rules

`tests/test_architecture.py` runs the **eleven** AST rules of
`utils/lint_architecture.py` with the suite. Like the submission test, they cover
failures that never show up as a red test.

**R1–R5 watch the agent**, and each one broke a submission or a decision once:

| | |
| --- | --- |
| R1 | Never `from <module> import <mutable>` — the importer freezes a copy and reads dead state forever, silently. |
| R2 | Nothing under `ptcg/cards/` or `ptcg/engine/` may touch state. (`ptcg/calc/` **may**: leaving it pure was attempted and proved to be a rewrite, not a move.) |
| R3 | In `main.py`, nothing binds a new name after `def agent` — the container keeps the *last* callable. |
| R4 | No lazy import of our own package, and no `import main` from inside it. |
| R5 | No module defines the same top-level name twice. Python keeps the last one, so the fix goes into the copy that is dead code. |

**R6–R8 watch the instruments**, and each comes from a defect that shipped green
in August 2026:

| | |
| --- | --- |
| R6 | A test that reads a `records/` file must carry a skip guard — that directory is re-harvested, and a census pinned to a board that a harvest took away goes red with nothing having changed. Citing a record in a docstring is provenance and stays allowed. |
| R7 | A two-arm `gate_*.py` must define **and call** `provenance()`. A gate that cannot see its own change reports neutral, and neutral orders a revert here. |
| R8 | Inside the DISCARD block, the turn-scoped flags may only be read through the horizon. On a forced discard, `supporterPlayed` and `energyAttached` describe what the **opponent** spent. |

**R9–R10 watch the agent's own discipline** — not a crash and not an
instrument, but a shape that reads as correct and is not:

| | |
| --- | --- |
| R9 | A per-option scorer prices an option; it does not write state. Modules under `ptcg/turn/options/` run **once per option**, over a list whose order belongs to the simulator, so anything they write is a function of that order. `we_go_first` was assigned while scoring the first-turn menu and survived as the value of the *last* option priced. |
| R10 | A field of `TurnPlan` or `AgentState` that nobody outside its module reads. A computed field with no consumer is a question the agent asked and then ignored, and from the outside it reads exactly like a fact in use — `op_wins_after_ko` was computed every turn and read by nobody for two days. Properties resolve back to the fields they touch, and `getattr(x, 'f', d)` counts as a read; without both, the rule accuses four load-bearing fields. Exempt with `# R10: <reason>` in the field's comment block — the reason is required. |

**R11 keeps the instruments away from the submission**:

| | |
| --- | --- |
| R11 | `utils/local_engine.py` loads a **modified** engine — one that honours the seed the official binary throws away, so games can be replayed. Tools may use it; `main.py` and `ptcg/` may not. What we submit runs on the shipped `cg/libcg.*`, and the local binary is git-ignored and simply absent on Kaggle. |

`tests/test_the_linter_learned_the_days_bugs.py` is the linter's own suite: it
plants each violation and confirms the rule catches it.

## 8. Metamorphic properties — no expected answer needed

The tests above all need somebody to know the right play. A **metamorphic**
property does not: it says how the answer must RELATE to another answer, so it
can be checked on boards nobody has ever looked at.

- **The menu's order must not decide**
  (`tests/test_the_menu_order_does_not_decide.py`). The agent answers with
  indexes into the list of legal options, so permuting the list may move the
  index and must not move the play. It catches what no red test does: a rule
  reaching for `option[0]`, a tie broken by position, a scan that stops at the
  first option of a kind instead of the best one.
- **The decision must stay decided** (`tests/decision_grid.py`,
  `tests/test_grid_attack_or_retreat.py`). Sweep an axis from calm to desperate --
  their prize pile shrinking, their attacker growing -- and a defensive decision
  may switch on once and must never switch back off. A rule that retreats at
  four prizes, attacks at three and retreats at two is two rules interfering,
  which is invisible on the single board each of them was measured on.

The grid also reports **where** a decision changes (`boundaries()`), which is the
list of thresholds the code really has as opposed to the ones its comments claim.

## 9. Mutation — measuring the suite instead of the agent

`utils/mutation_probe.py` rewrites one expression at a time and runs the suite
against each mutant. A mutant that survives is a line no test is watching. It is
the rule below, automated, and it found its first hole immediately: rewriting the
`>=` of `_hand_revealed_lethal_reply` as `>` -- so that a blow landing exactly on
the last hit point stopped counting as lethal -- passed the entire suite of the
day (1 498 tests at the time).

Use `--changed <ref>` when proposing a change: it mutates only the lines the diff
added, which answers "does the test I just wrote watch what I just wrote". That
is also the form CI runs, as `utils/gate_mutation.py --changed <base sha>`.

## 10. The coverage ratchet

`utils/gate_coverage.py --check` compares per-module coverage against
`coverage-floors.json` and fails when one drops by more than half a point. It is
a **ratchet, not a target**: nobody is chasing a number, but a module quietly
losing its watch is a real thing that happened — `ptcg/turn/options/evolve.py`
reached 6% covered while that week's diffs were being written into it, and
nothing said so.

Raising a floor needs no explanation. Lowering one does, and it belongs in the
commit message.

## A rule about tests themselves

**A green test proves nothing until you have seen it fail.** Every safety net in
this project was validated by mutation: inject the bug on purpose, confirm the
test goes red, then remove it.

State the sensitivity you measured, too. The permutation file above is honest
about its limit: a positional bias of +500 is invisible to it, +5000 is caught,
and a change to how TIES break is invisible at any size, because the synthetic
boards carry no ties. That is why the probe over played games exists next to it.

**Assert the reason, not only the choice.** The typical test here says "on this
board the agent picks option X", which pins the outcome and says nothing about
why. A rule can be deleted and the test stay green because a different rule
happened to pick the same option. `tests/rule_trace.py` asserts which rule in the
ladder produced the score, so the test fails when its own subject stops being the
reason.

## The main.py regression log

`main.py`'s own regressions used to live in one 9 500-line file. They are now
`tests/test_main_units.py` (unit tests of the helpers: damage, tracking, the
belief, the pure scorers) and `tests/test_main_regressions_1..8.py`, with
`tests/main_support.py` holding what more than one slice needs.

The split is **chronological, not thematic**, and that is on purpose: the file
grew by appending a test each time a game was lost, so neighbouring tests come
from the same session and often explain each other. Grouping them by matchup
would have meant reordering them, and the order is itself information. To find
the test for a rule, grep the rule's label or the card's name -- the names say
what they claim.
